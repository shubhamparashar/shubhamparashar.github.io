Teaching an agent to watch its own deploys

June 2026 · 15 min · ai agents, deploys, reliability

AI coding agents are good at writing changes and terrible at owning them. The dangerous moment is not generation; it is the hour after merge, when a plausible-looking change meets production and nobody is watching. The fix is not “trust the agent less.” It is giving the agent the same accountability loop you would demand from a human: prove the artifact, baseline the signals, watch, and know exactly how to undo.

1. Prove the artifact, not the pipeline

“CI is green” and “my code is running in prod” are different claims. Pipelines skip, cache, and deploy stale bundles. A sentinel’s first job after a deploy is to prove the running artifact contains the change: fetch the deployed bundle or image digest and grep for a marker only the new code has. Until that check passes, the deploy did not happen, whatever the pipeline says.

2. Baseline before, sweep after

An anomaly is only detectable relative to what normal looked like. Before the change goes live the sentinel captures a baseline: error classes and rates, p99, event-loop lag, log volume per log type. After, it sweeps on a schedule and compares. Crucially it asserts on logs, not HTTP status. Both of our worst near-misses passed every smoke test with clean 200s while background work silently failed; the string is not authorized in a log line was the only tell.

3. Count, don’t just match

A verification that checks “did the good thing happen?” misses “did it happen 31 extra times?”. Sentinels assert counts: expected emissions per event, exact sampling ratios, zero occurrences of forbidden classes. A passing proof that ignores cardinality once hid a bug that reported the same stall 31 times.

4. Pre-authorize the reversal

The worst time to design a rollback is during the incident. Every sentinel-watched change carries a reversal recipe written before the merge: the exact command, the task definition or version to restore, and the criteria that trigger it. When detection and reversal are both prepared, flagging a bad deploy is a one-line page instead of a war room.

What this buys you

With this loop an agent shipped a fleet resize and an observability overhaul (-83% log volume) with a 7-day automated vigil, 234 checks, zero incidents. The agent did not get more trustworthy. The system around it did, and that is the point: accountability is a property of the loop, not the model.
